# P4.2 — Neon development connection preparation

**Status:** the owner created the development project and stored both URLs in ignored `.env.local`. P4.3 verified pooled and direct read-only `SELECT 1` connections. Prisma 7.10.1 is configured and the local schema is validated; **no migrations or tables** were created. Auth and Storage integrations remain unimplemented. Do not use a production database for these steps.

1. Visit the [Neon Console](https://console.neon.tech/) and sign in. Choose **Free**; verify the current limits before creating anything.
2. Create a PostgreSQL project named `ayadatak-dev`. Choose an available region near the expected future Railway application region; do not assume a specific region is available or suitable for Auth/Storage until those integrations are tested. Use a development branch/database only.
3. Open the project's **Connect / Connection Details** panel. Select the intended development branch, database, and role. Turn **Pooled connection** on and copy its URL into `DATABASE_URL` in a local `.env.local` file. The pooled hostname normally contains `-pooler`.
4. Turn **Pooled connection** off and copy the direct URL into `DATABASE_URL_UNPOOLED` in the same `.env.local`. Keep the exact SSL parameters Neon supplies; do not manually construct or edit the passwords. The direct URL is reserved for future Prisma CLI/migration tooling; no migration is part of P4.2.
5. Start from the committed [`.env.example`](../.env.example) template. `.env.local` is Git-ignored. Keep both URLs out of chat, screenshots, issues, shell history, and commits. Never paste them here. If a URL leaks, rotate its database password in Neon.
6. Run `npm run db:check` from the project root. It loads the ignored local file, executes only `SELECT 1` through both URLs, and prints pass/fail without connection strings or driver errors. A sandbox without network access can fail even when the Neon credentials are valid; the owner-approved development check succeeded outside that sandbox. Do not paste a password-bearing URL into a command line.

P4.3 pinned `prisma`, `@prisma/client`, and `@prisma/adapter-neon` at **7.10.1**. The Prisma v7 [PostgreSQL setup](https://www.prisma.io/docs/orm/v7/core-concepts/supported-databases/postgresql) and [database connection guidance](https://www.prisma.io/docs/orm/v7/prisma-client/setup-and-configuration/databases-connections) place the **direct** CLI URL in `prisma.config.ts` and use a pooled runtime URL via a driver adapter. That separation is implemented; the generated client is local and Git-ignored. `npm run db:generate` regenerates it after schema changes. Do not run `prisma migrate`, `prisma db push`, or seeds before the next review.

Neon Auth and Neon Object Storage remain provisional. Creating the database project does not authorize or require enabling either product. The approved entitlement rules and schema direction are in [DATABASE_DESIGN.md](DATABASE_DESIGN.md); [TASKS.md](TASKS.md) tracks implementation status.
